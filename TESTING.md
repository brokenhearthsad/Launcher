# Тестирование

| Набор | Команда | Тестов |
|-------|---------|--------|
| Backend (pytest) | `cd backend && .venv\Scripts\python -m pytest` | 59 |
| Линтер | `cd backend && .venv\Scripts\ruff check app tests` | — |
| Frontend (Vitest) | `cd frontend && npm test` | 33 |
| Проверка типов | `cd frontend && npm run typecheck` | — |
| E2E (Playwright, production-режим) | `cd frontend && npm run build && npm run e2e` | 6 |

Backend: миграция старой базы v1 (копия создаётся, содержит старые данные, таблицы симулятора удалены,
логи сохранены, повторный запуск не делает копию), восстановление базы при сбое миграции, раздача
интерфейса и SPA-маршрутов, защита от выхода из папки, `Host`-заголовок, rate limit, остановка
(заголовок, отсутствие раннера, `should_exit`), ресурсы процесса, логи и их переживание
переконфигурации logging (регрессия), настройки, WebSocket.

## Ручная проверка PHASE 1 на Windows

1. `stop.bat` (на случай, если запущена старая версия) → `install.bat` → «Installation complete».
2. Убедиться, что в `backend\data\backups\` появилась копия `match_lab-…-pre-0002.db` (если база была).
3. `start.bat` → открывается http://localhost:8000, страница «Обзор», статус «Работает».
4. Диспетчер задач: один `python.exe` Launcher, `node.exe` нет; память < 150 МБ; ЦП ≈ 0 %.
5. «Логи» → обновить страницу (F5) — страница открывается (SPA).
6. «Настройки» → изменить интервал → «Сохранить» → обновить — значение сохранилось.
7. `stop.bat` → «Launcher stopped»; повторный `start.bat` работает.

Backend PHASE 2: psutil (реальные значения, скорости только со второго замера); GPU через поддельный NVML,
запасной `nvidia-smi` с ограничением частоты, отсутствие GPU с причиной; LibreHardwareMonitor на реальном
HTTP-сервере с деревом сенсоров Ryzen 5600X (выбор Tctl/Tdie, запятая как разделитель), недоступность →
«Нет данных»; минутные агрегаты с NULL; адаптивный интервал; VDF-парсер (новый/старый формат, ошибки);
поиск Steam (конфиг/реестр), Dota 2 во второй библиотеке, флаги состояния, отсутствие dota2.exe;
слежение за процессами (главный steam.exe, без лишних сканов, повторное использование PID); журнал событий;
слоты (10 шт., 5+5, валидация, один local_client, статус следует за процессами, история);
миграция 0002→0003 с копией; публикация событий из рабочих потоков.

## Ручная проверка PHASE 2 на Windows

1. `stop.bat`, скачать ветку заново, `install.bat` → в `backend\data\backups\` появилась копия `…pre-0003.db`.
2. `start.bat` → «Обзор»: реальные CPU/ОЗУ/GPU, состояние Steam и Dota 2.
3. «Система»: GPU — RTX 3050, видеопамять, температура GPU; диски C: и D:; сеть меняется при загрузке.
4. «Steam и Dota 2»: папка Steam, библиотеки, Dota 2 «установлена», сборка. Запустите Dota 2 сами —
   примерно через 5 с появятся PID и время работы, в «Событиях» — «Dota 2 запущен (PID …)».
5. «10 слотов»: переименовать слот и привязать к локальному клиенту — статус следует за Steam/Dota 2.
6. (Необязательно) LibreHardwareMonitor → Remote Web Server → Run; включить в Настройках → температура CPU.
7. Диспетчер задач во время игры: `python.exe` Launcher < 150 МБ, ЦП ≈ 0 %.
